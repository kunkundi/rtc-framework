# 客户端目录

客户端代码分为可执行程序、共享协议和可复用模块，xmake 目标名称不受目录分层影响。

## apps

- `rtc_console/`：支持桌面交互、音视频收发和无渲染运行的 RTC 操作端。
- `rtc_edge/`：工控机边缘端主程序，编排摄像头、音频和车辆控制配置。

应用目录只负责参数解析、依赖组装和生命周期管理。需要被多个应用复用的实现必须放入 `modules/`。

## 构建和运行

以下命令均在仓库根目录执行。运行前应先在 `config/rtc.cfg` 中配置可用的信令服务地址。

### rtc_console

构建并启动桌面界面：

```sh
xmake b rtc_console
xmake r rtc_console
```

`rtc_console` 房间输入框默认预填 `zhejianglab`，使用 `--room` 可指定其他房间：

```sh
xmake r rtc_console --room my-room
```

是否在登录 RTC 服务后自动打开房间由 `rtc.cfg` 控制，默认关闭：

```json
{
  "console": {
    "room": "zhejianglab",
    "auto_open_room": false,
    "device_slots": ["car_1", "car_2", "car_3", "car_4"]
  }
}
```

命令行 `--room` 会覆盖配置文件中的 `console.room`。

`console.device_slots` 按左上、右上、左下、右下绑定四台设备，省略时默认绑定 `car_1` 至 `car_4`。必须提供四个字符串，空字符串表示未绑定，非空 ID 不允许重复。设备乱序接入或离线不会改变其他格位，重连后回到原位置，但不会自动恢复驾驶接管。未绑定或未上报 ID 的连接不会进入田字格；重复在线 ID 会显示身份冲突并禁止控制。设备离线、等待画面、未绑定和身份冲突分别显示对应状态。

配置修改后需要重启控制台。

#### 键盘操作

以下业务快捷键主要在驾驶页生效；无渲染模式不支持这些界面操作。

| 按键 | 功能 | 生效条件与说明 |
| --- | --- | --- |
| `1` / `2` / `3` / `4` | 选择左上 / 右上 / 左下 / 右下设备 | 双目模式下按固定格位选择，再次按同一设备键取消选中；空格位和身份冲突设备不可选择 |
| `1` / `2` / `3` / `4` | 选择前 / 后 / 左 / 右摄像头 | 已选设备处于环视模式时切换对应单路画面，再次按同一路返回环视四格 |
| `S` | 切换双目与环视 | 需要已选中设备；环视单路也可通过此键返回双目 |
| `I` | 开关左右目像素交错显示 | 切换双目显示方式 |
| `Esc` | 环视单路返回双目；关闭全屏视频 | 两项操作可能同时发生；不是退出接管键 |
| `C` | 接管当前选中设备 | 设备绑定有效且控制通道就绪；清空旧输入，发送不带制动的停止帧，本地发送成功后进入接管，不代表设备已允许执行 |
| `Q` | 发送停止指令并退出接管 | 保留设备选择 |
| `X` | 发送紧急停止指令并退出接管 | 仅在接管状态下生效 |
| 上 / 下箭头 | 前进 / 后退输入 | 仅在接管状态下生效，按住持续输入 |
| 左 / 右箭头 | 左转 / 右转输入 | 仅在接管状态下生效，按住持续输入 |
| `Space` | 紧急停止输入 | 仅在接管状态下生效，按住发送，不退出接管 |
| `B` | 接管并制动 / 制动输入 | 未接管时接管当前选中设备，要求设备绑定有效且控制通道就绪，第一帧即请求满制动；接管后按住发送满制动，松开释放本地制动输入，不退出接管。文本输入框获得焦点时不触发，制动优先于键盘和手柄运动输入 |
| `D` / `N` / `R` | 请求前进档 / 空档 / 倒档 | 仅在接管状态下生效，单次按下触发，长按不重复发送 |
| `=`（与 `+` 同键） / `-` | 增加 / 减小油门设定 | 仅在接管状态下生效，支持长按重复 |

接管期间，在双目模式下使用数字键切换或取消设备选择，会先尝试停止原设备并退出接管；停止发送失败时可能取消切换，不会自动接管新设备。环视模式下数字键只切换摄像头，不更换设备。选中但未接管时，状态面板显示 `STANDBY`；接管后显示 `TAKEOVER`。

右上角 `CONTROL READY` 仅表示控制通道就绪，`TAKEOVER` 仅表示本地接管状态。`SAFETY` 根据设备保护停止反馈显示 `Protected` 或 `Clear`，没有反馈时显示 `Unknown`；它不能区分看门狗、安全锁定和侧向动作超时等具体原因。`BRAKE INPUT` 显示本地制动请求，不是硬件制动执行反馈。按 `C` 不再自动请求满制动，但停止方向仍可能使设备接口停止运动；设备端保护停止和安全联锁不受此修改影响。

文本输入框获得焦点时，方向控制、档位请求、油门调整和 `X` 被屏蔽；当前 `C`、`Q`、数字键及视图快捷键不受该保护。`W`、`A`、`F` 没有业务快捷键功能，`W/S/A/D` 不用于方向控制。

档位事务通过可靠的 `vehicle.event.v1` 通道定向发送，事件日志显示设备回执，状态面板的档位以设备反馈为准。本地发送成功不代表设备已执行换档或停止。方向键不会自动修改档位，设备端安全联锁和指令拒绝逻辑保持不变。网络停止指令不能替代本地制动、硬件急停和电机禁用逻辑。

桌面控制面板的 Audio Input 和 Audio Output 下拉框分别选择麦克风与播放设备。输入默认关闭，输出默认跟随系统设备；点击 Refresh Audio 可重新枚举设备。打开或加入房间时会自动注册音频轨道，之后仍可直接切换或关闭输入输出设备。

服务器无屏幕环境使用 `--no-render`，此模式不会创建 SDL 窗口或 OpenGL 上下文；`--headless` 是等价别名：

无渲染模式没有手动开房界面，需要将 `console.auto_open_room` 设置为 `true` 才会在登录后自动打开房间。

```sh
xmake r rtc_console --no-render --room my-room
```

也可以直接运行构建产物：

```sh
./build/runtime/rtc_console --no-render --room my-room
```

### rtc_edge

`rtc_edge` 仅在 Linux/Jetson 构建，需要摄像头、CUDA 和对应的 NVIDIA SDK 环境。使用构建时复制到运行目录的默认 `rtc.cfg` 启动：

```sh
xmake b rtc_edge
xmake r rtc_edge
```

使用 `--config` 指定其他配置文件；RTC、音频、摄像头、视觉和车辆控制运行参数均从该文件的 `edge` 配置段读取：

在 `edge` 配置段设置 `"device_id": "car_1"` 标识设备。ID 支持 1–64 个 ASCII 字母、数字、下划线、连字符和点；不同设备应设置不同 ID。`rtc_console` 按此 ID 匹配固定格位，并在视频标题和车辆控制目标中展示。旧边缘端配置仍可省略此字段，但不会进入控制台的固定格位。设备 ID 不是认证凭据，控制指令仍通过会话 ID 定向发送。

设备身份通过有序、可靠的 `device.identity.v1` 数据通道在每次通道打开时发送，载荷为不含终止零字节的 ID 文本（1–64 字节）；接收端拒绝不符合上述字符和长度规则的载荷。

#### 车辆控制调试模式

方向盘行程和舵机标定通过 `console.steering` 配置：

```json
"steering": {
  "wheel_range_deg": 900,
  "servo": {
    "left_deg": 60,
    "center_deg": 90,
    "right_deg": 120
  }
}
```

`wheel_range_deg` 是方向盘总行程，默认 900 度，即左右各 450 度；必须为有限正数。`servo` 是可选标定，角度以度为单位，上述数值仅用于说明格式，不是设备安全限位。启用标定时必须同时提供左限位、回中角和右限位，均为有限数，回中角严格位于两限位之间；允许左右数值反向，以适配反向安装。省略 `servo` 表示未标定，不采用默认硬件角度。真实机械限位必须由设备端独立保证，操作端配置不能替代硬件联锁。

接管后，左右箭头键分别减小、增大模拟方向盘角度，转动速度为每秒 180 度；松开保持，两键同时按下保持，角度限制在总行程的一半内。退出或重新接管时模拟角度清零。状态面板的 `WHEEL SIM` 横条游标显示此模拟位置，中线表示零位。当前尚未接入角度线协议或硬件执行映射；设备端仍收到原有左转、右转、回中指令，松开按键时设备指令仍回中，不代表硬件保持模拟角度。舵机标定参数仍仅用于配置加载与校验。

没有连接车辆硬件时，可将 `edge.vehicle_control.debug_mode` 设置为 `true`，并保持 `edge.dog_control.enabled` 为 `false`。重启使用该配置的 `rtc_edge` 后启用模拟接口，启动日志明确显示 `DEBUG vehicle simulation enabled`。此模式不会连接 rosbridge 或向硬件发送命令，仅接受合法的驾驶和档位请求，用于验证接管、`B` 制动输入、`D/N/R` 换档回执和状态面板；反馈档位是模拟值，不代表硬件执行。狗动作不支持模拟，仍返回拒绝。

调试模式默认关闭，省略字段也保持关闭；与狗硬件控制同时启用时配置加载失败。协议与序号校验、300 ms 默认看门狗、安全停止和锁定规则保持不变，普通安全锁定仍需重新建立控制会话，调试模式不会自动解锁。恢复硬件使用前必须关闭调试模式，并接入对应真实控制接口。配置需写入实际运行实例加载的文件，仅修改源配置不会改变已运行实例。

```sh
xmake r rtc_edge --config /path/to/rtc.cfg
```

也可以直接运行构建产物：

```sh
./build/runtime/rtc_edge --config ./build/runtime/rtc.cfg
```

## tests

- `rtc_dual_camera_headless/`：双摄像头、RTC 和视觉链路的集成测试程序。
- `rtc_receiver_headless/`：RTC 视频接收和帧落盘测试程序。

测试程序保留原有 xmake 目标名，但不属于正式发布应用。

## protocols

- `vehicle/`：车辆控制、档位事务和状态反馈协议。
- `vision/`：视觉能力、类别表和检测帧协议。

协议 schema、nanopb 生成代码和 C++ codec 由客户端应用共享，不归属于某个具体可执行程序。详细约束与生成方式见 `protocols/README.md`。

## modules

- `audio/`：基于 SDL3 的音频设备枚举、PCM 采集与低延迟播放。
- `camera/`：公共 V4L2 能力以及 `single/`、`dual/` 单双摄采集和转换。
- `logging/`：基于 spdlog 的公共日志模块。
- `runtime/`：客户端进程生命周期、配置路径解析和可复用 RTC 会话。
- `edge/`：边缘端的单相机、双目和环视推流编排。
- `vision/`：检测发送、双目融合、YOLO 消费与推理适配。
- `vehicle/`：车辆控制接收、安全门控和本地车辆控制适配。

模块公共头文件统一放在 `include/<命名空间>/`。跨模块包含必须使用完整前缀，例如：

```cpp
#include "rtc_runtime/rtc_session.h"
#include "rtc_audio/audio_device.h"
#include "rtc_camera/single/async_image_source.h"
#include "rtc_camera/dual/async_image_source.h"
#include "rtc_edge/dual_camera_streaming_module.h"
#include "rtc_vision/vision_detection_sender.h"
#include "rtc_vehicle/vehicle_control_module.h"
```

`src/internal/` 仅供所属模块内部使用，不应加入其他模块的公共 include 路径。
